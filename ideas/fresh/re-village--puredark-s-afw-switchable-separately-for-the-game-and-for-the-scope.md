# PureDark's AFW, switchable separately for the game and for the scope

Order: 4008

> "what would ne amazing is if PureDark's AFW could be applied separately to the game and the
> scope, can have both, only the game with AFW and normal scope, or normal game and AFW scope, now

Four combinations, each the player's choice: AFW on both, on the game only, on the scope only, or
on neither. The point is that the scope picture and the main view are two separate drawings with
two different jobs — the main view wants smoothness, the scope wants sharpness at a distance — so
one setting for both is always a compromise for one of them.

It sits beside the idea above rather than replacing it: that one is a small sharpening step of our
own; this one would hand the same job to a far more capable tool that already exists.

**What it'd take:** not known, on purpose. The questions to answer when the time comes: whether AFW
runs on this game at all alongside the VR mod; whether it can be pointed at a second picture rather
than only the main one; and what PureDark's terms allow — it is his work, so this would be built
*with* it, never by copying it, and he would be credited and asked.

**Read on 2026-09-21, at Tefa's request (reading only — nothing run):** AFW stands for Alternate
Frame Warping. The game draws fewer pictures and AFW manufactures the missing ones by bending the
ones that exist — one eye made from the other, or this frame made from the last. To do that it
needs to know how far away everything is and how it is moving, and it learns both by **listening in
on the game's own upscaler (DLSS / FSR 2 / XeSS)**. Tefa's own try on Silent Hill 2: *"the
performace boost was incredible with just a little artifacting around the hands and weapons"* —
and PureDark's notes name exactly that artefact and fix it per game.

⭐ **The encouraging part:** the bending itself is a sealed add-on of PureDark's with a published
"socket", and that socket is plain graphics-card language — it does not mention Unreal anywhere it
has to. So it is not welded to Unreal games in principle.

⚠️ **The three real obstacles, none looked into:** (1) Village's built-in upscaler is, as far as
remembered, the old kind that does not carry the distance-and-movement information AFW listens for
— unchecked; (2) the scope is a third picture, not an eye, so only the "this frame from the last"
mode could apply to it, and the scope's zoom would magnify any bending mistakes about 2.4×;
(3) the socket looks built for one instance per game, not two. And before any of it: **it is
PureDark's work and what he allows is not known** — ask first.
